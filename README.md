# hospital-sim-env

The simulated hospital with a surgical wing, and the surgical instruments handled in it. Nothing here knows
about a particular robot: there is no robot model and no controller code, so a different humanoid can be
dropped into the same building. It depends on no sibling repo. Most people will get it through the master repo
`hospital-sim`, which clones every component next to each other and carries `env.sh` and `docs/interfaces.md`,
the contract between the parts. Paths below are relative to this folder.

## Contents

| Folder | What |
|---|---|
| `isaac/` | Isaac Sim 6.0 scene: NVIDIA's Isaac `hospital.usd` building plus a surgical wing (link corridor, surgical corridor, pre-op, PACU, sterile store, scrub room, operating theatre). `isaac/scene/layout.py` is the single source of truth for room geometry, doorways, furniture and cameras; `isaac/scene/build_hospital.py` turns it into the USD layers under `isaac/usd/`. No physics is authored here |
| `objects/` | Scrub-nurse props as MJCF and physics-ready USD: 7 surgical instruments, tool rack, instrument table, surgeon mannequin, generated by `objects/build_objects.py`. `objects/placements.yaml` is the single source of object poses for both simulators; `objects/catalog.json` is the generated summary other components read |

Both halves share one world frame (the Isaac world; the wing origin is at (17.93, -4.45, 0)).

## Who consumes it

- `g1-mujoco-sim` rebuilds the walls from `isaac/scene/layout.py`, extracts furniture boxes from `isaac/usd/hospital_g1.usd`,
  and attaches `objects/mjcf/*.xml` at the `objects/catalog.json` poses.
- `g1-isaac-sim` layers the robot and physics on top of `isaac/usd/hospital_g1.usd` and places `objects/usd/*.usd`.
- `hospital-sim-ros2` derives the mission locations from the object poses and uses the same frame for navigation.
- `hospital-sim-perception` uses the instrument names in `objects/catalog.json` as its labels and the objects as
  synthetic-data sources.

## Assets that are not in git

The scene references NVIDIA Isaac Sim 6.0 assets and the NVIDIA Isaac for Healthcare (i4h) sim-ready asset
catalog, version 0.7.0. They are fetched with NVIDIA's own tooling (the `i4h-digital-twin` repository and its
asset helper, which resolves assets as `$I4H_ASSET_DOWNLOAD_DIR/<catalog hash>/...`). `isaac/i4h_env.sh` records
the layout this repo was built against:

| Variable | Value |
|---|---|
| `ISAAC_ASSET_ROOT` | `$HOME/isaacsim_assets/Assets/Isaac/6.0` |
| `I4H_REPO` | `$HOME/isaacsim_assets/i4h-digital-twin` |
| `I4H_ASSET_DOWNLOAD_DIR` | `$HOME/isaacsim_assets/Assets/Isaac/Healthcare/0.7.0` |
| `I4H_ASSET_ROOT` | `$I4H_ASSET_DOWNLOAD_DIR/724f82e` |

Two sets of symlinks point into that copy and have to exist on your machine:

- `isaac/i4h_assets` points at `I4H_ASSET_ROOT` (the catalog folder `.../Healthcare/0.7.0/724f82e`).
- `isaac/assets/isaac` and `isaac/assets/i4h` are what the USD layers and `objects/build_objects.py` load through.
  `isaac/scene/select_assets.py lite|full` switches them between the original assets and an 8 GB-GPU mirror
  with decimated meshes and capped textures (`~/isaacsim_assets/lite/...`), see `isaac/README.md`.
